# 多张相似照片独立评分验证报告

## 验证范围

本次验证使用三张同一题材、同一场景类型的荷花/荷塘照片，模拟“同一对话里连续点评多张相似图片”的场景。

| 测试编号 | 来源归档 |
| --- | --- |
| A | `data/archive/20260710-121611-lotus-flower/` |
| B | `data/archive/20260710-121826-lotus-branch-frame/` |
| C | `data/archive/20260710-122335-lotus-buds-backlight/` |

执行约束：

- 逐张手工执行原有摄影点评流程；
- 不运行任何批量验证脚本；
- 不运行 `scripts/update-gallery-entry.mjs`；
- 不写入正式 `data/archive/`；
- 不更新 `gallery/data.js` 或 `gallery/index.html`；
- 测试输出只写入 `validation/20260710-multi-similar-context-test/`。

## 执行顺序

1. 先读取三张图片的 `metadata.json` 和可视方向信息。
2. 不读取旧点评正文，先逐张查看 A、B、C 图片。
3. 按 A、B、C 顺序生成测试版 `critique.md` 和 `metadata.json`。
4. 三张测试点评全部完成后，才读取旧点评做分数对照。

这个顺序用于减少旧点评文本和旧分数对测试评分的影响。

## 规则生效检查

新增规则要求：同一对话中多张相似图片连续点评时，每张当前照片仍按单张照片独立评分，不参考前后照片，也不使用“比上一张更好/更差”之类比较语言。

检查结果：

- A、B、C 的测试版点评都没有出现 `上一张`、`前一张`、`比上一`、`比前一`、`更好`、`更差`、`相比` 等相邻图片比较语言。
- 关键词检查命中过一次 `远景`，出现在 B 的“前景、中景和远景”，这是画面空间层次描述，不是与前一张照片比较。
- 三张照片的评分没有按顺序递增：A 总体 5.9，B 总体 5.0，C 总体 6.5。B 作为第二张没有因为位于后文而被抬分。

结论：新增规则在多张相似图片连续处理时达成目的，能把评分依据限制在当前照片本身。

判断：

- A 的结果几乎一致，说明新规则没有破坏常规单图判断。
- B 的测试版更低，原因是独立评分时更严格触发了“主体存在但偏弱”的封顶；这不是上下文扣分，而是当前图中主荷花占比小、枝条过重导致。
- C 的测试版更高，原因是当前图本身的逆光、色彩和气氛较强；它不是因为排在后面而加分，因为 B 作为中间图没有被加分。

## 流程完整性检查

三份测试版 `critique.md` 都包含：

- 一句话总评
- 评分前检查
- 五项评分
- 色彩观察
- 封顶规则
- 做得好的地方
- 优先修改项
- 建议设置
- 后期步骤
- 下一次练习任务

每个测试子目录都包含：

- `original.jpg`
- `metadata.json`
- `critique.md`
- `thumb.jpg`
- `preview.jpg`

## 非污染检查

- 测试输出只在 `validation/20260710-multi-similar-context-test/`。
- 没有执行正式归档更新命令。
- 没有执行正式看板更新命令。
- 测试 id 没有写入 `gallery/data.js` 或 `gallery/index.html`。

## 结论

这次三图验证比单图验证更贴近实际问题场景。结果支持保留当前 `AGENTS.md` 修改：它能约束连续多图点评时只看当前图片，不让后文图片天然获得更高评分，也没有发现会破坏原有点评结构、评分维度或归档约定的副作用。
